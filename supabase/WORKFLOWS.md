# Campus workflows database contract

Apply `20261005114655_campus_workflows.sql` after the two existing migrations. Tests in `tests/campus_workflows.sql` run inside a rollback transaction against a disposable Supabase-compatible database. They cover authorization, strict below-59 alerts, late report deduplication, London BST/GMT deadlines, notification acknowledgements and private material access. Run `node scripts/test-database.mjs` from `kharis` with local PostgreSQL tools installed. The runner creates a uniquely named disposable database, applies the checked-in auth/storage bootstrap and all migrations, runs the rollback assertions, and drops the database. It refuses non-local hosts and ignores inherited PostgreSQL connection settings. Optional local CI settings are KOC_TEST_PGHOST, KOC_TEST_PGPORT, KOC_TEST_PGUSER and KOC_TEST_PGPASSWORD. The local role needs database/role creation privileges for the minimal Supabase stubs. Verified locally on PostgreSQL 14.19; live Supabase advisors remain a separate deployment check.

Profiles add role `cluster` and `cluster_id`. A cluster account requires a cluster; campus accounts require a campus. Admins configure existing users through `admin_update_user(p_user_id,p_role,p_status,p_campus_id,p_full_name,p_cluster_id)`; the final argument is optional. Cluster leads have read-only access to their cluster's reports, grades and contacts. Accounts are not fabricated: named cluster leads must receive verified real accounts separately.

Clusters seed London/Modupe, Midlands/Elyon, South/Lindsay, North/Naa, South East/Zipporah, West/Chiedza. Campus regions map directly to these clusters, with existing `West England` mapped to `West`. `Colleges` needs an explicit decision and remains unassigned. Campuses add latitude, longitude, address, meeting_info and contact_email. Coordinates remain unset until verified; campus metadata is public, so do not put private personal information there.

`submit_grade(p_campus_id,p_student_name,p_course,p_assessment,p_percentage,p_assessment_date,p_notes)` creates a grade. Campus users can submit only their campus; admin/editor users can submit any campus; cluster leads cannot submit. Grade fields are id, campus_id, student_name, course, assessment, percentage, assessment_date, notes, submitted_by, created_at. Percentages accept at most two decimal places. Every percentage strictly below 59 creates a notification per active admin/editor and the active cluster lead of that campus; 59 does not. Grades are immutable through the browser API.

Contacts use id, campus_id, full_name, phone, fellowship_attended, branch_attended, notes, is_active, created_by, created_at, updated_at. Campus/admin/editor users may insert and update; campus_id and created_by cannot be changed after insertion. Use is_active=false to archive. Cluster leads can read only their own cluster's contacts. Anonymous visitors have no access.

Notifications use id, recipient_id, kind (`late_report` or `low_grade`), title, message, campus_id, report_id, grade_id, created_at, read_at. Only the recipient's active account can read a notification or call `acknowledge_notification(p_notification_id)`. First acknowledgement time is retained. Report insert triggers notify active admin/editor accounts for initial submissions after Friday 22:00 Europe/London. Updating a report does not create duplicate alerts. Existing report functions validate Friday/reporting season and derive the deadline from the configured season (currently 22:00 Europe/London). These are in-app alerts, not email or push delivery.

`quarter_campus_totals()` returns year, quarter, campus_id, campus_name, reports, attendance, prayer_minutes, evangelism_minutes, outreach_outings. RLS scopes results. `season_campus_summary()` also supports cluster scopes.

Materials use id, title, description, object_path, campus_id, uploaded_by, is_active, created_at, updated_at. A null campus_id publishes to every active account; a campus_id limits readers to that campus and its cluster plus overall leads. Upload PDFs to private bucket `koc-materials`, maximum 20 MiB, path `<uploader UUID>/<new UUID>.pdf`, then insert matching metadata. Only admin/editor accounts can upload/publish. File read policies check visible, active material metadata. Uploader-owned unpublished orphan PDFs may be deleted after a failed publish. Published uploads are immutable; archive material metadata to remove reader access. Do not generate long-lived signed links; authenticated file fetching retains access controls. Browser viewing cannot guarantee prevention of screenshots, recording or file extraction; UI deterrents must not claim DRM protection.
